# نظام كول سنتر التبرعات

نظام لإدارة كول سنتر التبرعات. المدير يرفع داتا المتبرعين ويوزعها على الايجنتس، وكل ايجنت يشوف المتبرعين المخصصين له بس ويسجل نتيجة كل مكالمة. المدير بعدها يطلع تقارير بأداء كل ايجنت.

```
donation-call-center/
├── backend/     FastAPI + SQLite (API + business rules + tests)
├── frontend/    واجهة عربية RTL (HTML/JS بدون build) بيقدمها الباك إند
└── prototype/   محاكي HTML تفاعلي مستقل لتجربة الورك فلو بدون سيرفر
```

## التشغيل

```bash
cd donation-call-center/backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m app.seed --demo      # اختياري: بيانات تجريبية (4 ايجنتس + 300 متبرع)
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

افتح `http://localhost:8000`:
- المدير: `admin` / `admin123` (غيّرها فوراً، أو حدد `CALLCENTER_ADMIN_USER` و`CALLCENTER_ADMIN_PASSWORD` قبل أول تشغيل)
- البيانات التجريبية: `agent1` .. `agent4` / `agent123`
- توثيق الـ API: `http://localhost:8000/docs`

متغيرات البيئة:

| المتغير | الاستخدام |
|---|---|
| `CALLCENTER_DB` | رابط قاعدة البيانات (الافتراضي `sqlite:///./callcenter.db`، وينفع PostgreSQL) |
| `CALLCENTER_SECRET` | مفتاح توقيع الجلسات. **لازم تحدده في الإنتاج**، وإلا كل الجلسات بتتمسح مع كل restart |
| `CALLCENTER_TOKEN_TTL` | مدة الجلسة بالثواني (الافتراضي 12 ساعة) |

الاختبارات:

```bash
cd donation-call-center/backend && pytest
```

## الورك فلو

1. **استلام الداتا**: المدير يرفع ملف CSV (أعمدة: الاسم، الموبايل، المدينة، المصدر، آخر تبرع، ملاحظات؛ بالعربي أو الإنجليزي). الأرقام بتتوحد (`+20`/`0020`/أرقام عربية) والمكرر بيتشال.
2. **التوزيع**:
   - **متوازن**: اللي قائمته المفتوحة أقل ياخد الأول.
   - **بالتساوي**: بالدور.
   - **عدد ثابت لكل ايجنت**.
   - كلهم بفلتر مدينة / مصدر / حالة، وفيه كمان توزيع يدوي لمتبرعين محددين وسحب.
   - **نقل الداتا**: لو ايجنت غاب أو مشي، متبرعينه المفتوحين يتوزعوا بالتساوي على ايجنت واحد أو أكتر.
   - كل عملية توزيع بتتسجل في سجل.
3. **الايجنت**: يشوف داتته بس، مرتبة كالتالي: المتابعات المستحقة الأول، بعدين الجديد، بعدين المهتمين، بعدين المواعيد الجاية. زرار «اتصل بالتالي» بيفتح المتبرع ومعاه سجل مكالماته وتايمر للمكالمة.
4. **نتائج المكالمة** (14 نتيجة):

| النتيجة | التأثير |
|---|---|
| اتبرع | مبلغ + طريقة دفع، والمتبرع يتقفل |
| وعد بالتبرع (هيتبرع) | مبلغ + موعد تحصيل (مطلوب) |
| عنده نية / مهتم | يفضل في القائمة، والموعد اختياري |
| طلب معاودة الاتصال | موعد مطلوب |
| طلب تفاصيل (واتساب) | متابعة |
| لا يرد / مشغول / الموبايل مغلق | يرجع تلقائياً بعد 4 / 2 / 6 ساعات؛ بعد 5 محاولات متتالية بدون رد يبقى «استنفد المحاولات» |
| معندوش نية / اتبرع لجهة أخرى | يتقفل |
| طلب عدم الاتصال | يتقفل ويتعلّم «لا تتصل» |
| شكوى | تظهر للمدير |
| رقم خطأ / الرقم غير موجود | يتقفل كرقم غير صالح |

   المدير يقدر يعيد فتح أي متبرع مقفول.
5. **التقارير** (بأي فترة، ولكل ايجنت أو للكل):
   - مكالمات مقابل الهدف اليومي
   - نسبة الوصول
   - تبرعات ومبالغها
   - وعود ومبالغها، ونسبة الوعود اللي اتحصّلت
   - عنده نية، معاودة، لا يرد، مغلق، رفض، رقم خطأ، شكاوى
   - نسبة التحويل
   - متوسط مدة المكالمة
   - القائمة المفتوحة والمتابعات المتأخرة
   - توزيع النتائج، والمكالمات والمبالغ يومياً
   - أفضل ساعة للاتصال
   - الوعود القائمة
   - تصدير CSV بيفتح في Excel بالعربي

## الـ API (مختصر)

| Endpoint | الوصف |
|---|---|
| `POST /api/auth/login` | تسجيل الدخول، بيرجع Bearer token |
| `GET/POST/PATCH /api/users` | إدارة الفريق (المدير) |
| `GET /api/donors` · `POST /api/donors` · `POST /api/donors/import` | المتبرعين (الايجنت بيشوف داتته بس) |
| `GET /api/donors/{id}` · `PATCH /api/donors/{id}` | التفاصيل والسجل / التعديل وإعادة الفتح |
| `POST /api/donors/{id}/calls` | تسجيل نتيجة مكالمة |
| `GET /api/agent/queue` · `GET /api/agent/followups` | قائمة الاتصال والمتابعات |
| `POST /api/distribution/auto` · `assign` · `unassign` · `transfer` | التوزيع |
| `GET /api/distribution/summary` · `history` | حمل كل ايجنت وسجل التوزيع |
| `GET /api/reports/overview` · `agents` · `outcomes` · `daily` · `pledges` | التقارير |
| `GET /api/reports/export/agents.csv` · `calls.csv` | تصدير |

## المحاكي التفاعلي

`prototype/call-center-prototype.html` صفحة واحدة بتشتغل في المتصفح ومعاها بيانات تجريبية: 160 متبرع، و4 ايجنتس، وتاريخ 3 أيام. فيها:

- التبديل بين المدير وأي ايجنت
- تقديم الوقت المحاكى (ساعة / يوم)
- «محاكاة يوم عمل»

القواعد فيها هي نفس قواعد الباك إند.
